# Design portfolio site

A personal portfolio built with [Next.js](https://nextjs.org/) for my wife - a product designer - her previous page was built in SquareSpace.

---

## Why Next.js?

When I set out to build my wife's portfolio, I had a choice to make: keep it simple with plain HTML/CSS, reach for a JavaScript framework I already knew, or use this as an opportunity to learn something new. I chose Next.js — and it turned out to be one of the most valuable decisions in my learning journey so far.

### A Framework That Grows With You

Next.js sits in a sweet spot: it's approachable enough to get started quickly, but deep enough that there's always more to learn. I didn't need to understand every feature on day one. I could start by building simple pages and gradually discover concepts like file-based routing, server components, and static generation as I needed them — rather than being overwhelmed upfront.

### File-Based Routing Just Made Sense

One of the first things that clicked for me was Next.js's file-based routing. Adding a new page means creating a new file. There's no router configuration to wrangle, no boilerplate to copy-paste. This let me focus on *what* I was building rather than *how to wire it together*, which is exactly what I needed as someone still solidifying my fundamentals.
It was a step up for me from simple React applications that need external routers like React Router or TanStack.

### Learning How the Web Actually Works

Choosing Next.js pushed me to understand the distinction between server-side and client-side rendering — something I'd glossed over before. Building this portfolio gave me real hands-on context for questions like: *When should something be a Server Component vs. a Client Component? What gets sent to the browser, and when?* These aren't abstract concepts anymore; they're decisions I made while building pages in this very project.

### Production-Ready Habits From the Start

I wanted to pick up habits that would transfer to professional work, not just hobbyist projects. Next.js is widely used in the industry, has excellent documentation, and has a thriving ecosystem. Learning it for my portfolio meant I was also learning something that would matter in a real job — image optimization, performance considerations, deployment with Vercel — all baked in.

### The Ecosystem Opened Doors

Once I was in the React/Next.js ecosystem, a whole world of libraries, tutorials, and community resources became accessible to me. Stuck on something? Chances are someone else has solved it and written about it. That support system made learning less lonely and faster.

---

## What I Learned Along the Way

- **React fundamentals** — components, props, state, and hooks in a real project context
- **App Router & file-based routing** — understanding how Next.js maps files to URLs
- **Server vs. Client Components** — knowing when to use each and why it matters
- **Static Site Generation (SSG)** — pre-rendering pages for fast load times
- **CSS Modules / Tailwind CSS** — scoping styles and building responsive layouts
- **Deployment** — shipping to production via Vercel
